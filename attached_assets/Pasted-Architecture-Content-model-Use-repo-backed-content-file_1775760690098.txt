Rendering rule

All primary content must be present in generated HTML at build time. JS should only enhance UX, never inject the main article body.

That preserves the SEO advantages you already have.

CMS plan

Use Decap CMS mounted at /admin.

Decap can manage Git-backed content, supports folder collections for repeating content like blog posts, and supports files collections for singleton config content. Editorial workflow can create PRs for unpublished content.

admin/config.yml shape

Use:

one folder collection for posts
one files collection for site settings
media folder for images
public folder for emitted asset paths

Example shape:

backend:
  name: github
  repo: your-org/your-repo
  branch: main

media_folder: "src/assets/img/uploads"
public_folder: "/assets/img/uploads"

collections:
  - name: "posts"
    label: "Posts"
    folder: "src/content/posts"
    create: true
    slug: "{{slug}}"
    extension: "md"
    format: "frontmatter"
    fields:
      - { label: "Title", name: "title", widget: "string" }
      - { label: "Description", name: "description", widget: "text" }
      - { label: "Date", name: "date", widget: "datetime" }
      - { label: "Updated", name: "updated", widget: "datetime", required: false }
      - { label: "Slug", name: "slug", widget: "string" }
      - { label: "Tags", name: "tags", widget: "list", required: false }
      - { label: "Author", name: "author", widget: "string" }
      - { label: "Draft", name: "draft", widget: "boolean", default: false }
      - { label: "OG Image", name: "ogImage", widget: "image", required: false }
      - { label: "Body", name: "body", widget: "markdown" }

  - name: "settings"
    label: "Settings"
    files:
      - label: "Site Settings"
        name: "site"
        file: "src/content/settings/site.json"
        fields:
          - { label: "Site Name", name: "siteName", widget: "string" }
          - { label: "Site URL", name: "siteUrl", widget: "string" }
          - { label: "Default Description", name: "defaultDescription", widget: "text" }
Auth choice

Two simple choices:

GitHub backend if only a few technical editors
Git Gateway if you want friendlier non-dev editing via Netlify Identity

Decap documents Git Gateway as the proxy layer for authenticated editors without direct repo write access.
